# BRIEF@1：离线单会议室预约器的合成输入

这是作者为教学构造的需求材料，不是访谈、客户授权或批准记录。用它检查模板如何从原始目标形成需求；不引入生产数据。

<a id="u1"></a>
## U1：创建与确认

“我希望按固定时间格预约一间会议室，并明确知道是否预约成功，输入不合法时不要悄悄创建。”

<a id="u2"></a>
## U2：冲突与取消

“两场会议不能抢同一段时间；前一场结束时下一场可以开始。取消后应能重新预约，旧取消请求不能误删新预约。”

<a id="u3"></a>
## U3：日程与利用情况

“我需要按时间查看有效预约，并知道全天已用、空闲时长、格数和利用率。”

## 本例明确规定的范围与假设

- C1：只管理一间房、一天，08:00—18:00；开放容量固定为 600 分钟。
- C2：输入为严格 HH:MM，15 分钟网格，正长度；确认包含 ID、标准时间与时长。
- C3：使用半开区间；端点相邻不冲突。取消从有效集移除，ID 在本进程不复用。
- C4：单进程、串行、内存实现；排除并发、多房间、跨日、持久化、认证和图形界面。
- C5：返回日程为副本；利用率显示一位小数。没有响应时间或内存字节预算承诺。
- C6：所有人名/角色都是教学标签；无真实人类验收或治理批准。需求 ID 在本例 catalog@1 中登记，实际 Skill 项目仍需通过其规范登记与受理流程。

需求的内容版本均为 @1；各阶段文档修订均为 doc rev 1，但属于不同快照。TR1 不能因教学包最终包含 TR4 就预先引用 TR4 的通过结果。
