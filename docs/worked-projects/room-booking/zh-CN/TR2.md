| 场景 | 来源/目标 | 正常及异常步骤 | 边界/前提 |
| --- | --- | --- | --- |
| SC-1 | U1 / ir-01@1 | 提交08:00—09:00；确认；另提交09:20—10:00应拒绝 | 空日；严格格式；边界17:45—18:00可用 |

### D-SR-01 · sr-01@1

**上层精确版本及目标：** ir-01@1 — 在单日开放时段内，用户可按 15 分钟粒度创建预约并获得明确确认；无效输入必须明确拒绝。

**场景 / 设计前提：** BRIEF@1/C1–C5；SC-1；TR2 第 2 章

**推导与必要性：** 从上层目标中提取本模块/系统必须承担的可观察责任：系统只接受 HH:MM 格式、真实时钟值且满足 08:00≤start<end≤18:00、端点均在 15 分钟网格上的预约。

**计算 / 图示 / 逻辑依据：** 将 SC-1 的输入转为距午夜分钟 m=60h+min。开放容量=(18−8)×60=600 分钟，共 600/15=40 格；合法端点为 480+15k，k=0…40，且开始端点小于结束端点。格式、时钟值与业务窗口须分层检查。

**方案取舍与适用边界：** 使用整数分钟避免浮点边界；09:20 虽是时钟值，仍因不在网格上被拒绝。

**得到的需求陈述：** 系统只接受 HH:MM 格式、真实时钟值且满足 08:00≤start<end≤18:00、端点均在 15 分钟网格上的预约。

### D-SR-02 · sr-02@1

**上层精确版本及目标：** ir-01@1 — 在单日开放时段内，用户可按 15 分钟粒度创建预约并获得明确确认；无效输入必须明确拒绝。

**场景 / 设计前提：** BRIEF@1/C1–C5；SC-1；TR2 第 2 章

**推导与必要性：** 从上层目标中提取本模块/系统必须承担的可观察责任：合法且无冲突的请求应创建一条有效预约，返回本进程内不复用的 ID、起止时间和时长；拒绝不得改变有效列表或消耗 ID。

**计算 / 图示 / 逻辑依据：** 用户必须能把确认与后续取消对象对应，所以确认含稳定 ID 和输入窗口；仅返回成功标志不够。先检查再写入，避免错误路径留下预约或跳过编号。

**方案取舍与适用边界：** 递增编号只保证本进程唯一；不宣称跨重启唯一或磁盘事务原子性。

### D-SR-03 · sr-03@1

**上层精确版本及目标：** ir-02@1 — 有效预约不得重叠，相邻预约允许；用户取消有效预约后可立即重新预约该时段。

**场景 / 设计前提：** BRIEF@1/C1–C5；SC-2；TR2 第 2 章

**推导与必要性：** 从上层目标中提取本模块/系统必须承担的可观察责任：按半开区间 [start,end) 判断冲突；相邻端点允许，任意正长度重叠拒绝且原列表不变。

**计算 / 图示 / 逻辑依据：** 两段不相交当且仅当 b≤c 或 d≤a；取反得到 a<d 且 c<b。用严格小于才能使 [08:00,09:00) 与 [09:00,09:30) 相邻而不重叠；包含、被包含和相同区间仍冲突。

**方案取舍与适用边界：** 扫描当前有效预约，复杂度 O(n)；本例最多 40 条正长度预约，无需区间树。

**得到的需求陈述：** 按半开区间 [start,end) 判断冲突；相邻端点允许，任意正长度重叠拒绝且原列表不变。

### D-SR-04 · sr-04@1

**上层精确版本及目标：** ir-02@1 — 有效预约不得重叠，相邻预约允许；用户取消有效预约后可立即重新预约该时段。

**场景 / 设计前提：** BRIEF@1/C1–C5；SC-2；TR2 第 2 章

**推导与必要性：** 从上层目标中提取本模块/系统必须承担的可观察责任：取消已存在 ID 应移除其有效预约并释放时段；未知或重复取消返回 NOT_FOUND，不影响其他预约且旧 ID 不再复用。

**计算 / 图示 / 逻辑依据：** 释放意味着该条记录不再参与冲突扫描；立即以相同窗口重新创建必须成功。若复用旧 ID，延迟到达的重复取消可能误删新预约，因此编号在取消后也只能继续递增。

**方案取舍与适用边界：** 未知取消明确报错，不把重试说成已再次取消；不设计分布式幂等协议。

**得到的需求陈述：** 取消已存在 ID 应移除其有效预约并释放时段；未知或重复取消返回 NOT_FOUND，不影响其他预约且旧 ID 不再复用。

**验证方法与预期：** test；C-SR-04；计划用例 V-SR-04。按上列要求逐项断言；此阶段没有实际通过结果。

### D-SR-05 · sr-05@1

**上层精确版本及目标：** ir-03@1 — 用户可查看按时间排序的有效预约，以及当天已用/空闲分钟数、时段数和利用率。

**场景 / 设计前提：** BRIEF@1/C1–C5；SC-3；TR2 第 2 章

**推导与必要性：** 从上层目标中提取本模块/系统必须承担的可观察责任：日程只列有效预约，按开始分钟、结束分钟、ID 排序，输出标准 HH:MM 及时长；修改返回数据不得改变系统状态。

**计算 / 图示 / 逻辑依据：** SC-3 可以先预订晚会议再订早会议，故创建顺序不等于日程顺序。每条输出来自当前有效集；返回新字典而不暴露内部对象，使查看操作保持只读。

**方案取舍与适用边界：** 稳定排序规则显式声明；单房间无重叠时同开始时间不会共存，但次级键使格式确定。

### D-SR-06 · sr-06@1

**上层精确版本及目标：** ir-03@1 — 用户可查看按时间排序的有效预约，以及当天已用/空闲分钟数、时段数和利用率。

**场景 / 设计前提：** BRIEF@1/C1–C5；SC-3；TR2 第 2 章

**推导与必要性：** 从上层目标中提取本模块/系统必须承担的可观察责任：以 600 分钟为固定分母，计算有效预约的占用/空闲分钟、15 分钟格数及一位小数的利用率；取消后即时重算。

**计算 / 图示 / 逻辑依据：** SR-03 保证有效区间不重叠，所以并集长度=Σ(end−start)。两段 08:00—09:00 与 09:30—10:30 共 60+60=120 分钟，空闲 480，已用格 8，空闲格 32，利用率 120/600×100=20.0%。

**方案取舍与适用边界：** 每格占比 15/600×100=2.5%，一位小数足够精确；不以当天最早/最晚会议跨度作分母。

**得到的需求陈述：** 以 600 分钟为固定分母，计算有效预约的占用/空闲分钟、15 分钟格数及一位小数的利用率；取消后即时重算。

## 6. 明确接口与跨模块约束

API：book(start,end)→确认或明确错误；cancel(id)→取消确认或NOT_FOUND；agenda()→新列表；summary()→新汇总对象。输入与冲突均须在写入前拒绝。不存在网络、仓库锁或平台权限接口。取消与创建协作保证旧ID不复用；只读输出不得泄露可写内部对象。
