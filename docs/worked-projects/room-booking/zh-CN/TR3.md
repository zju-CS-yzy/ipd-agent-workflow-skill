## 1. 明确设计范围与 TR2 输入

输入为 [TR2@doc1](TR2.md)、[SR-TR2@doc1](SR-TR2.md)、D-SR-01…06及C1—C6。没有新增用户目标，六条SR版本均保持1。架构分析完成后，在第5章形成12条AR，再登记到教学catalog；起草时不要求这些AR已存在。

<!-- ipd-section:architecture -->
## 2. 选择总体架构并说明模块职责

选用单一Calendar对象持有有效预约集与单调计数器；校验、呈现和指标为逻辑职责单元。调用链：

```text
book -> parse -> window/grid -> scan(active) -> create -> confirmation
cancel(id) -> remove active entry; counter stays monotonic
agenda/summary -> read active set -> fresh output
```

相比双台账或数据库，单一有效集使冲突与汇总使用同一事实；C4排除了持久化、并发要求。此章只关联SR，不提前列尚未推导的AR。

| 组件 / 模块 | 架构视图引用 | 支撑 SR 精确版本 | 职责 | 部署 / 依赖 | 关键决定 / 理由 |
| --- | --- | --- | --- | --- | --- |
| validation | TR3 §2–3 | sr-01@1 | 时钟与窗口 | ledger | integer minutes |
| ledger | TR3 §2–4 | sr-02@1, sr-03@1, sr-04@1 | 单一有效集/计数器 | serial process | precheck before mutation |
| presentation | TR3 §2–3 | sr-05@1 | 排序/格式/副本 | ledger | read only |
| metrics | TR3 §4 | sr-06@1 | 分钟/比例 | ledger; SR-03 | fixed 600 min |

<!-- ipd-section:behavior -->
## 3. 分析交互、数据与关键机制

请求序列：解析失败→拒绝；窗口失败→拒绝；有冲突→拒绝；仅全部预检通过后写入一条并推进ID。取消删除有效集条目但不回退ID。08:00—09:00 与09:00—09:30相邻，因为前一区间不含09:00；08:45—09:15同时满足两条严格不等式，所以冲突。只读输出新对象避免外部篡改。

<!-- ipd-section:quality -->
## 4. 论证质量属性、预算与设计风险

网格端点有41个，正长度非重叠预约最多40条；冲突扫描O(n)，日程排序O(n log n)，不把复杂度换算成未经测量的毫秒。占用U=Σ(end−start)，不重叠和窗口约束保证0≤U≤600。每段长度是15的倍数，U×1000/600为整数，可精确显示一位小数利用率。单进程输入拒绝前零写入不等于持久事务保证。

### D-AR-01 · ar-01@1

**上层精确版本及目标：** sr-01@1 — 系统只接受 HH:MM 格式、真实时钟值且满足 08:00≤start<end≤18:00、端点均在 15 分钟网格上的预约。

**场景 / 设计前提：** BRIEF@1/C1–C5；SC-1；TR3 第 2—4 章，父 SR 的已确定条件

**推导与必要性：** 从上层目标中提取本模块/系统必须承担的可观察责任：解析器将两位 HH:MM 且 0≤h≤23、0≤m≤59 转为 60h+m；其他输入返回明确格式或时钟错误。

**计算 / 图示 / 逻辑依据：** SR-01 的业务比较需先得到统一整数。08:00=480、09:15=555、18:00=1080；9:00 缺前导零，09:75 分钟越界，二者不能被宽松转换为预约。

### D-AR-11 · ar-11@1

**上层精确版本及目标：** sr-06@1 — 以 600 分钟为固定分母，计算有效预约的占用/空闲分钟、15 分钟格数及一位小数的利用率；取消后即时重算。

**场景 / 设计前提：** BRIEF@1/C1–C5；SC-3；TR3 第 2—4 章，父 SR 的已确定条件

**推导与必要性：** 从上层目标中提取本模块/系统必须承担的可观察责任：对当前有效集累加 end−start 得到占用分钟，空集为零；取消项不得计入。

**计算 / 图示 / 逻辑依据：** SR-03 保证不重叠，故可直接求和。两个 60 分钟区间之和为 120；取消其中一项后为 60，而不是把 08:00—10:30 的 150 分钟全部计入。

**方案取舍与适用边界：** 显式依赖不重叠不变量；未来若允许重叠必须改为区间并集算法。

**得到的需求陈述：** 对当前有效集累加 end−start 得到占用分钟，空集为零；取消项不得计入。

### D-AR-12 · ar-12@1

**上层精确版本及目标：** sr-06@1 — 以 600 分钟为固定分母，计算有效预约的占用/空闲分钟、15 分钟格数及一位小数的利用率；取消后即时重算。

**场景 / 设计前提：** BRIEF@1/C1–C5；SC-3；TR3 第 2—4 章，父 SR 的已确定条件

**推导与必要性：** 从上层目标中提取本模块/系统必须承担的可观察责任：以固定 600 分钟计算 free=600−occupied、used_slots=occupied/15、free_slots=free/15，利用率保留一位小数且不使用不适用分母。

**计算 / 图示 / 逻辑依据：** 每格为 2.5%，故十分之一百分比单位=occupied×1000/600，是整数，不需舍入。空日为 0/600=0.0%，满日为 600/600=100.0%，120 分钟为 20.0%。

**方案取舍与适用边界：** 使用整数十分位，避免浮点显示误差；600 固定且非零，无空列表除零。

**得到的需求陈述：** 以固定 600 分钟计算 free=600−occupied、used_slots=occupied/15、free_slots=free/15，利用率保留一位小数且不使用不适用分母。
